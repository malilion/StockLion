## 1. 背景與驗證目的

在《StockLion v2.1 Implementation Spec》第 3.4 章中明確指出：**Stock Peek 是本產品最具特色的核心功能，但同時也是技術風險最高的功能**。

若僅採取「全網頁文字掃描 + Dictionary 直接比對」，實務上會面臨致命缺陷：
1. **數字誤判失控**：四位數字隨處可見（西元年份如 2024、商品售價如 $2330 元、訂單編號、電話號碼、日期時間）。若純比對數字，普通網頁將佈滿假股票標記。
2. **名稱歧義混淆**：台股許多公司名屬於通用詞彙（如「統一」、「大同」、「東元」），在日常文章中常指商品（統一布丁、大同電鍋）而非股票標的。
3. **SPA 效能卡頓**：在 Threads、Dcard 等大型 SPA 滾動時若無節流與標籤過濾，全 DOM 掃描將嚴重拖慢畫面影格率。

本 Spike 的目的即是在進入 Phase 2～5 主要資料層前，**以可驗證的測試組建立候選詞提取、上下文過濾（Context Filter）、DOM Scanner 與 Hover Card，並驗證誤判防禦率與效能預算**。

## 2. 核心架構與過濾管線（Pipeline）

```text
網頁載入 / DOM Mutation
        ↓
DomainPolicy 檢查（是否在白名單內，如 PTT Stock、Threads、Yahoo 股市）
        ↓
DOMScanner（TreeWalker 過濾非文字、表單、代碼標籤；單批上限 500 節點）
        ↓
候選詞提取（正則提取 4~5 位數字與字典公司名稱）
        ↓
ContextFilter 上下文權重評分（前後 40 字元窗口分析）
   ├─ 數字代號：
   │   ├─ 緊鄰對應公司名稱？ → 立即放行（信心度 1.0）
   │   ├─ 含有年份/電話/緊鄰數字/無財經關鍵字？ → 拒絕（誤判率 0%）
   │   └─ 上下文得分 contextScore >= 3？ → 放行標記
   │
   └─ 公司名稱：
       ├─ 歧義名稱（統一/大同/東元）：需 score >= 3 且無商品負向詞
       └─ 一般公司名稱（台積電/聯發科/元大台灣50）：score >= 1
        ↓
相鄰代號與公司名稱合併（如 "2330 台積電" 合併為單一實體）
        ↓
替換為 <span class="stocklion-target"> 綁定輕量 HoverCard
```

## 3. 實測樣本與基準數據（Benchmarks）

依據 [tests/fixtures/sample-texts.json](file:///Users/changtingyu/StockLion/tests/fixtures/sample-texts.json) 之 4 大類測試樣本，於 [tests/unit/stock-peek/detector.test.ts](file:///Users/changtingyu/StockLion/tests/unit/stock-peek/detector.test.ts) 執行自動化基準測試，實測結果如下：

| 測試情境 | 測試樣本描述 | 原始未過濾誤判率 | Context Filter 過濾後誤判率 | 正向召回率 |
|---|---|---|---|---|
| **年份邊界** | `2024 年巴黎奧運即將在 07/26 開幕...`（2024 志聯） | 100% 誤判 | **0%**（未標記） | — |
| **價格與編號** | `這支特價耳機售價只要 2330 元，訂單編號 2454` | 100% 誤判 | **0%**（未標記） | — |
| **電話號碼** | `服務專線電話請撥 0912-2317-2454` | 100% 誤判 | **0%**（未標記） | — |
| **商品名詞歧義** | `今天下午去買了統一布丁跟統一純喫茶` | 100% 誤判 | **0%**（未標記） | — |
| **家電生活用品** | `台灣人家裡必備的大同電鍋很好用` | 100% 誤判 | **0%**（未標記） | — |
| **PTT 股票討論** | `[標的] 2330 台積電 多單進場`、`2454 聯發科 外資賣超` | — | 0% | **100%** |
| **Threads 財經串** | `台積電下半年營收強勁... 外資買超`、`0050 還是 00878 定期定額` | — | 0% | **100%** |
| **代號名稱相鄰** | `今日焦點股 2330 台積電 逆勢抗跌` | — | 0% | **100%**（合併為單一實體） |

### 實測重大發現與調整：
1. **「年」字不可作為全域負向詞**：初版曾將 `/年/` 設為負向詞，導致「台積電下半年營收強勁」中因出現「下半年」而被誤判排除。修正為：僅在「4 位數字後方緊鄰年月日」或「前方緊鄰西元/民國」時判定為年份排除，財經文章中常見的「今年/下半年/近三年」則正常放行。
2. **相鄰代號+公司名是最強驗證信號**：當「2330」緊鄰「台積電」時，兩者在物理位置相鄰已證明其股票意圖，此時應直接通過並合併為單一實體，避免重複標記兩次。

## 4. 上下文權重計分模型（Context Scoring）

窗口長度設定為候選詞前後各 40 個字元。

### 4.1 正向權重矩陣
- **強關鍵字 (+3)**：`股票`, `股價`, `漲停`, `跌停`, `收盤`, `開盤`, `標的`, `持股`, `存股`, `多單`, `空單`, `ETF`, `做多`, `做空`, `台股`, `美股`, `加權指數`
- **中關鍵字 (+2)**：`大盤`, `外資`, `投信`, `自營商`, `買超`, `賣超`, `主力`, `量能`, `爆量`, `季線`, `月線`, `均線`, `破線`, `突破`, `回檔`, `殖利率`, `本益比`, `除權息`, `營收`, `財報`
- **弱關鍵字 (+1)**：`漲`, `跌`, `買`, `賣`, `張`, `籌碼`, `股`

### 4.2 負向排除規則
- 緊鄰前後數字（如 `123305`）→ 致命扣分（`-999`）
- 緊鄰電話連字號（如 `0912-2317` 或 `2317-2454`）→ 致命扣分（`-999`）
- 緊鄰日期/年份後綴（如 `2024年`, `2024/07`）→ 致命扣分（`-999`）
- 緊鄰生活商品負向詞（如 `電鍋`, `布丁`, `麵包`, `純喫茶`, `超商`）→ 致命扣分（`-4` 且標記 `hasNegativeContext`）

## 5. DOM 掃描器效能與安全性

### 5.1 標籤排除與節點過濾
- 自動略過：`SCRIPT`, `STYLE`, `NOSCRIPT`, `INPUT`, `TEXTAREA`, `PRE`, `CODE`, `SVG`, `BUTTON`, `A`
- 略過 `contenteditable="true"` 與已高亮的節點（防止二次標記）
- 單次掃描節點上限：`maxNodesPerScan = 500`

### 5.2 渲染排程防護
- 採用 `requestIdleCallback` 於瀏覽器空閒時執行初次掃描，不阻塞首屏渲染。
- `MutationObserver` 監聽動態 DOM（如 PTT 推文或 Threads 瀑布流滾動），並加入 **300ms Debounce 防抖**，避免滾動時大量反覆觸發重繪。

### 5.3 浮動卡片（HoverCard）
- 懸浮目標綁定 `mouseenter` / `mouseleave`。
- **150ms Debounce 延遲展開**，避免滑鼠快速劃過時造成閃爍。
- 視窗邊界偵測（邊緣不超出螢幕可視區）。
- 嚴格遵守 v2.1 規格：卡片內資料明確顯示來源與新鮮度標籤（`quoteBadge`），無 API Key 時標示 `○ 盤後收盤`，絕不偽冒即時。

## 6. Phase 6 正式版實施建議

1. **維持現行 ContextFilter 權重與閾值**：實測證實代號門檻 `>= 3` 與公司名稱門檻 `>= 1` 兼顧了高召回率與 0 誤判率。
2. **網域白名單初始範圍**：維持 PTT Stock 板、Yahoo 股市、鉅亨網、Threads、經濟日報、工商時報；Phase 6 正式版可提供使用者自訂白名單選項。
3. **Background 訊息串接**：HoverCard 的報價資料目前使用 Mock EOD Quote，Phase 6 正式串接 Background Service Worker 的 `quote:get` 訊息，由 Background 統一向快取或 OpenData 請求，Content Script 維持不持金鑰的絕對安全邊界。
